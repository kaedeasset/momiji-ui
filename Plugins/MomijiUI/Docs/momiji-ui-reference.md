# MomijiUI Reference

This reference is for MomijiUI 0.1.0 (2026-10-21).

MomijiUI is a UI framework where you write screens as JSON and draw them with the same layout in Unreal Engine (UE) and in the browser. This reference lists every screen-JSON key, all 17 node types and their keys, the enumerated values, animation, themes and diagnostic codes. The tables are generated by a script from the validator tables of the two implementations (UE and browser).

- The steps to run the sample, write your own screen and check it are in the [setup guide](momiji-ui-guide.md). Start there if you are new.

## 1. How to read this reference

### 1.1 Units and colours

- **Screens are written for 1280 × 720.** Positions and sizes (`x` `y` `w` `h` `pad` `gap` `margin` `wrapW` `lineH`) are logical px on that canvas. The real window shows it scaled with the aspect ratio kept; the rest is letterboxed.
- **`fontSize` is in points.** On screen it is `fontSize × 4/3` px (17 → 23 px). 16 when omitted.
- **Colours are `#rrggbb` or `#rrggbbaa`.** Any other text (`red`, for example) is ignored and the default colour is used (diagnostic `bad-color`).
- Text uses the bundled BIZ UDP Gothic font, not the operating system's fonts (§12).

### 1.2 Reading the tables

- **Type**: the value type the validator checks. "(not checked)" means the validator accepts the key as known but does not check its shape (the shape is given under "What to write").
- **Default**: the value used when you omit the key. "—" means there is no default (the key does nothing unless written).
- **Browser**: "Yes" means both UE and the browser draw it. "**UE only**" means only UE draws it; the browser's validator accepts it as a known key but the browser does not draw it (the extra drawing styles, borders and so on; §11).
- The node-type tables do not repeat the common keys (§3.1). Every node type also accepts the keys in §3.1.
- Key names are case-sensitive. Keys starting with `_` are notes; neither the validator nor the renderers read them.

### 1.3 The two implementations

| | UE | Browser |
|---|---|---|
| Drawn with | Slate (`SKaedeUiCanvas` in `MomijiUISlate`) | HTML `<canvas>` (`momiji-ui.mjs`) |
| Screen JSON | the same file | the same file |
| Role | reference implementation | follows UE |

The same screen JSON with the same values gives the same layout, the same hit areas and the same focus movement in both implementations (§11).

## 2. Screen JSON

A screen file is an object whose `root` holds the node tree. A file without `root` is read as a single node.

```json
{
 "root": {
  "type": "VerticalLayout", "anchor": "center", "w": 400, "h": 200, "pad": 20, "gap": 12,
  "children": [
   { "type": "Label", "text": "Hello {name}", "h": 32, "fontSize": 20, "align": "center" },
   { "type": "Button", "id": "ok", "text": "OK", "action": "ok", "h": 44 }
  ]
 }
}
```

Top-level keys:

<!-- momiji-ui-ref:begin doc-keys -->
| Key | What to write |
|---|---|
| `id` | The screen's name (optional). The renderers do not use it. In conformance fixtures it is the fixture's name |
| `note` | A note for people (optional). Neither the renderers nor the validator read it |
| `title` | The screen's title (optional). The renderers do not use it |
| `root` | The root node of the screen's tree (an object). When it is present, the top-level keys are checked too. Without it, the whole file is read as one node |
| `bind` | Values to draw with, {strings, vars, lists} (optional). The UE launch option -KaedeUiShot and the conformance check draw with them. In a game the host passes the values, so you do not need it |
| `scenarios` | Interaction scenarios for the conformance check (optional, fixtures only). Do not write it in game screens |
| `invalid` | When true, the conformance check compares only the diagnostics (marks a fixture that contains deliberate errors). Do not write it in game screens |
| `host` | A place for values that the program using the screen (the host) reads (any object). The renderers and the validator do not look inside |
<!-- momiji-ui-ref:end doc-keys -->

Screen JSON has no version number. Valid JSON written today keeps the same sizes in later versions.

## 3. Node types

A node's kind is set by `type`, and nodes nest through `children`. Layout containers (VerticalLayout, HorizontalLayout, GridLayout, ScrollView, Modal) position their children. Panel does not.

![All 17 node types on one screen (UE, midnight theme). Polygon and Divider are currently drawn in UE only](images/momiji-ui/components.png)

### 3.1 Common keys

<!-- momiji-ui-ref:begin common-keys -->
Keys you can write on every node type (25).

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `type` | string | Panel | Yes | The node type (one of the 17 in §3). Panel when omitted |
| `id` | string | — | Yes | The node's name. Focus, scroll position, animation and text-field contents are tracked by it. Give one to every node that holds state (pressable, text field, ScrollView, Modal). Inside a list use a data key, such as "row:{item.id}" |
| `x` | number | 0 | Yes | Left edge (logical px). Inside a layout container the parent decides it |
| `y` | number | 0 | Yes | Top edge (logical px). Inside a layout container the parent decides it |
| `w` | number | 0 | Yes | Width (logical px). For a child of a vertical container, omitting it fills the parent's width |
| `h` | number | 0 | Yes | Height (logical px). When omitted it is measured from the content (layout containers, wrapping Label) or 28 |
| `margin` | number | 0 | Yes | Outer margin inside a layout container (the same on all four sides) |
| `flex` | number | 0 | Yes | For a child of a vertical/horizontal container, the share of the leftover space (1 and 2 split it 1:2) |
| `minW` | number | 0 | Yes | Minimum width when space is shared by flex (child of a horizontal container) |
| `minH` | number | 0 | Yes | Minimum height when space is shared by flex (child of a vertical container) |
| `anchor` | string | — | Yes | Snap to a screen edge or the centre (values in §4.1). Resolved once before drawing |
| `showIf` | string | — | Yes | A condition (§5.2). When false the node and its children are removed |
| `hideIf` | string | — | Yes | A condition (§5.2). When true the node and its children are removed |
| `enabledIf` | string | — | Yes | A condition (§5.2). When false the node cannot be pressed (drawn dimmed) |
| `highlightIf` | string | — | Yes | A condition (§5.2). When true the node is highlighted (same as highlight) |
| `enabled` | boolean | true | Yes | When false the node cannot be pressed (drawn dimmed) |
| `focusable` | boolean | true | Yes | When false the node is skipped by arrow-key and gamepad focus (it can still be clicked) |
| `highlight` | boolean | false | Yes | When true the node is highlighted (panels and containers get an accent border and a lighter fill; outline buttons get an accent border) |
| `action` | string | — | Yes | The string delivered to the host when pressed; the host decides what it means. Besides Button, writing it on Panel, Image, layout containers, Slider, Toggle and ToggleGroup items makes them pressable. TextInput delivers it on Enter |
| `anim` | object | — | Yes | Animation (§7). Animated nodes need an id or an action |
| `offset` | (not checked) | — | UE only | [x, y]. Shifts the node from where the layout put it (it may stick out). UE only |
| `rotate` | number | 0 | UE only | Degrees. Rotates the node and its content around its centre. UE only |
| `skewX` | number | 0 | UE only | Degrees. Skews the node and its content horizontally around its centre. UE only |
| `opacity` | number | 1 | UE only | 0 to 1. Fades the node together with its content. UE only |
| `glow` | (not checked) | — | UE only | {size, color}. Draws a soft glow behind the node. UE only |
<!-- momiji-ui-ref:end common-keys -->

### 3.2 Panel

<!-- momiji-ui-ref:begin type-Panel -->
A panel. **It does not lay out its children** (their x, y, w and h are used as screen positions as written; use VerticalLayout to stack). Write an action to make it pressable.

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `variant` | string | a panel in the theme's panel colour | Yes | Look: spacer (draws nothing), light, dark, atelier-surface, atelier-card, atelier-icon-tile |
| `color` | string | theme panel | Yes | Fill colour (#rrggbb or #rrggbbaa) |
| `borderColor` | string | theme panelEdge | UE only | Border colour. UE only |
| `borderWidth` | number | theme border | UE only | Border width (px). 0 draws no border (nor the theme's double line or ornaments). UE only |
| `gradient` | (not checked) | — | UE only | {"dir": "v" or "h", "stops": [["#rrggbbaa", 0], ["#…", 1]]}. Fills with a linear gradient (overrides color). UE only |
| `shape` | string | rect | UE only | Box shape: rect, hex (both ends pointed), tagL, tagR (one end pointed), slant (parallelogram). UE only |
| `shapeInset` | number | 0.35 × height | UE only | Depth of the points (px). UE only |
| `edge3d` | (not checked) | — | UE only | {light, dark, width}. A bevelled edge (top and left light, bottom and right dark). UE only |
| `innerBorder` | (not checked) | — | UE only | {color, width, inset}. A second line inside the border. UE only |
| `clip` | boolean | false | UE only | When true the content is clipped to the box. UE only |
| `backdropBlur` | number | 0 | UE only | Strength (2 to 20). Blurs what is behind the panel. UE only |
| `highlightTextColor` | string | — | UE only | Colour of the text inside while highlighted. UE only |
| `selectable` | boolean | false | Yes | When true the text of the Labels inside can be selected with the mouse and is copied to the clipboard on release (§6.2) |
| `children` | array | — | Yes | Array of child nodes |
| `repeat` | string | — | Yes | A list name (§5.1). The template is copied once per item of the list the host passes, and the copies become the children |
| `template` | object | — | Yes | The template for repeat (one node) |
| `templates` | object | — | Yes | {"<kind>": template}. The item's templateKey value chooses the template |
| `templateKey` | string | — | Yes | The item key that chooses a template from templates |

Example:

```json
{ "root": { "type": "Panel", "x": 40, "y": 40, "w": 400, "h": 160, "variant": "dark",
  "children": [
   {"type": "Label", "x": 60, "y": 60, "w": 360, "h": 32, "text": "Score {score}"}
  ] } }
```
<!-- momiji-ui-ref:end type-Panel -->

### 3.3 Image

<!-- momiji-ui-ref:begin type-Image -->
An image or a coloured rectangle. With neither sprite nor color it is filled with the theme's panel colour.

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `sprite` | string | — | Yes | The image location (a key). The host resolves it (UE: relative to the project; browser: imageSource) |
| `fit` | string | contain | Yes | How the image fits (values in §4.1) |
| `color` | string | theme panel | Yes | Fill colour when there is no image |
| `borderColor` | string | — | UE only | Border colour. A border is drawn only when this or borderWidth is written (square corners, over the image). UE only |
| `borderWidth` | number | — | UE only | Border width (px). UE only |
| `gradient` | (not checked) | — | UE only | Fills the rectangle with a linear gradient (same shape as for Panel; only when there is no sprite and color is also written). UE only |
| `slice` | (not checked) | — | UE only | [left, top, right, bottom] (image px). Nine-slice stretching. UE only |
| `tile` | boolean | false | UE only | When true the image is tiled. UE only |
| `src` | (not checked) | — | UE only | [x, y, w, h] (image px). Uses part of the image. UE only |

Example:

```json
{ "root": {"type": "Image", "x": 40, "y": 40, "w": 320, "h": 180, "sprite": "Plugins/MomijiUI/Fixtures/images/landscape.png", "fit": "cover"} }
```
<!-- momiji-ui-ref:end type-Image -->

### 3.4 Label

<!-- momiji-ui-ref:begin type-Label -->
Text. Single-line text is centred vertically in the box. With wrapW it wraps, and its height comes from the number of lines.

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `text` | string | — | Yes | The text. {key} is replaced by a value (§5). \n breaks the line |
| `fontSize` | number | 16 | Yes | Font size (points; × 4/3 px on screen) |
| `font` | string | bold | Yes | Weight: bold (bold), main (regular). logo is bold in the browser and regular in UE |
| `align` | string | left | Yes | Horizontal alignment (values in §4.1) |
| `center` | boolean | false | Yes | When true the text is centred (old form; align wins when present) |
| `wrapW` | number | 0 | Yes | Wrap width (px). With it the text is multi-line, flowing down from the top left |
| `lineH` | number | fontSize × 30/22 (30 without fontSize) | Yes | Line height (px; only when wrapping) |
| `ellipsis` | boolean | false | Yes | When true text that does not fit is cut at the end with "…" (single line) |
| `textColor` | string | theme textPrimary (textDim when disabled) | Yes | Text colour |
| `runs` | array | — | Yes | [{text, bold, color, ruby}]. Changes colour, bold and ruby per span (drawn instead of text). UE also reads size (span size) and icon, src (an image in the line) |
| `textOutline` | (not checked) | — | UE only | {width, color}. Outlines the text. UE only |
| `textGlow` | (not checked) | — | UE only | {size, color}. A glow around the text. UE only |
| `letterSpacing` | number | theme | UE only | Letter spacing (px). UE only |
| `monoDigits` | boolean | false | UE only | When true digits are set at the same width. UE only |
| `highlightTextColor` | string | — | UE only | Text colour while inside a highlighted container. UE only |

Example:

```json
{ "root": { "type": "VerticalLayout", "anchor": "center", "w": 480, "h": 160, "pad": 16, "gap": 8,
  "children": [
   {"type": "Label", "text": "Chapter {chapter}", "fontSize": 20, "align": "center", "h": 32},
   {"type": "Label", "text": "A long line of text that wraps inside the box.", "font": "main", "wrapW": 440, "textColor": "#9aa6b8"}
  ] } }
```
<!-- momiji-ui-ref:end type-Label -->

| `edge3d` | (not checked) | — | UE only | {light, dark, width}. A bevelled edge. UE only |
| `textOutline` | (not checked) | — | UE only | {width, color}. Outlines the text. UE only |
| `textGlow` | (not checked) | — | UE only | {size, color}. A glow around the text. UE only |

```json

  "children": [
   {"type": "Button", "id": "ok", "text": "OK", "action": "ok", "w": 160},
   {"type": "Button", "id": "cancel", "text": "Cancel", "action": "cancel", "variant": "ghost", "w": 160, "enabledIf": "canCancel"}
  ] } }
```

### 3.6 Slider

<!-- momiji-ui-ref:begin type-Slider -->
A track with a bar filled up to the value. The ratio (0 to 1) of where it was pressed is delivered to the host as the value (kind: slider).

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `bindVar` | string | — | Yes | The value's name. The host's number value (vars) goes into value |
| `value` | number | 0 | Yes | Value from 0 to 1 |
| `color` | string | theme accent | Yes | Colour of the filled bar |
| `text` | string | — | UE only | A number from 0 to 1 as text (such as "{hp}"). Used instead of value when written. UE only |
| `gradient` | (not checked) | — | UE only | Fills the bar with a linear gradient. UE only |
| `edge3d` | (not checked) | — | UE only | {light, dark, width}. A bevelled edge on the track. UE only |
| `shape` | string | — | UE only | Shape of the track and bar (same values as Panel). UE only |
| `shapeInset` | number | — | UE only | Depth of the points (px). UE only |
| `borderColor` | string | — | UE only | Border colour of the track. UE only |
| `borderWidth` | number | — | UE only | Border width of the track (px). UE only |

Example:

```json
{ "root": { "type": "VerticalLayout", "anchor": "center", "w": 400, "h": 80, "pad": 16, "gap": 8,
  "children": [
   {"type": "Label", "text": "Volume", "h": 24},
   {"type": "Slider", "id": "volume", "bindVar": "volume", "action": "set:volume", "h": 14}
  ] } }
```
<!-- momiji-ui-ref:end type-Slider -->

### 3.7 Toggle

<!-- momiji-ui-ref:begin type-Toggle -->
A check box with text on its right. Pressing it delivers the new true/false to the host (kind: toggle). The hit area is the box + 10 + the text width.

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `bindVar` | string | — | Yes | The value's name. It is on when the host's number value (vars) is not 0 |
| `on` | boolean | false | Yes | Whether it is on |
| `text` | string | — | Yes | Text to the right of the box |
| `font` | string | main | Yes | Text weight |

Example:

```json
{ "root": { "type": "VerticalLayout", "anchor": "center", "w": 400, "h": 60, "pad": 16,
  "children": [
   {"type": "Toggle", "id": "subtitles", "bindVar": "subtitles", "action": "toggle:subtitles", "text": "Subtitles"}
  ] } }
```
<!-- momiji-ui-ref:end type-Toggle -->

### 3.8 ToggleGroup

<!-- momiji-ui-ref:begin type-ToggleGroup -->
Exclusive choice like tabs. The children (each item's text and action) share the width equally, and the chosen item gets an accent bar on top. Pressing delivers the item's index to the host (kind: toggle).

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `bindVar` | string | — | Yes | The value's name. The host's number value (vars) goes into selected |
| `selected` | number | 0 | Yes | Index of the chosen item (from 0) |
| `children` | array | — | Yes | Array of items (each with text and action) |

Example:

```json
{ "root": { "type": "VerticalLayout", "anchor": "center", "w": 480, "h": 64, "pad": 8,
  "children": [
   { "type": "ToggleGroup", "id": "speed", "bindVar": "speed", "h": 40,
    "children": [
     {"id": "speed-0", "text": "Slow", "action": "speed:0"},
     {"id": "speed-1", "text": "Normal", "action": "speed:1"},
     {"id": "speed-2", "text": "Fast", "action": "speed:2"}
    ] }
  ] } }
```
<!-- momiji-ui-ref:end type-ToggleGroup -->

### 3.9 ScrollView

<!-- momiji-ui-ref:begin type-ScrollView -->
Stacks its children vertically and scrolls vertically when they overflow (flex has no effect). When the content is taller than the box, 10 is taken from the children's width for the scroll bar. Outside the visible area nothing is drawn or pressable.

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `pad` | number | 0 | Yes | Inner padding |
| `gap` | number | 8 | Yes | Space between children |
| `variant` | string | — | Yes | light or dark fills the background |
| `color` | string | — | Yes | Background colour (filled when written) |
| `selectable` | boolean | false | Yes | When true the text of the Labels inside can be selected and copied (§6.2) |
| `children` | array | — | Yes | Array of child nodes |
| `repeat` | string | — | Yes | A list name (§5.1) |
| `template` | object | — | Yes | The template for repeat |
| `templates` | object | — | Yes | {"<kind>": template} |
| `templateKey` | string | — | Yes | The item key that chooses a template from templates |

Example:

```json
{ "root": { "type": "ScrollView", "id": "log", "x": 40, "y": 40, "w": 600, "h": 300, "pad": 8, "gap": 4, "selectable": true, "repeat": "lines", "children": [],
  "template": {"type": "Label", "text": "{item.text}", "font": "main", "wrapW": 560} } }
```
<!-- momiji-ui-ref:end type-ScrollView -->

### 3.10 Modal

<!-- momiji-ui-ref:begin type-Modal -->
A full-screen dimmer with a board in the middle. The board is w × h (480 × 320 by default) and centred when x and y are 0. Children are stacked vertically. A Modal is its own focus group: while it is open, nothing behind it gets focus or input.

| Key | Type | Default | Browser | What to write |
|---|---|---|---|---|
| `text` | string | — | Yes | Heading (36 high, 4 below the board's top). With it, the children start 48 below the top |
| `dim` | boolean or number | true | Yes | When false no dimmer is drawn |
| `pad` | number | 0 | Yes | Inner padding of the board |
| `gap` | number | 8 | Yes | Space between children |
| `color` | string | theme panel | Yes | Board colour |
| `borderColor` | string | — | UE only | Board border colour. UE only |
| `borderWidth` | number | — | UE only | Board border width (px). UE only |
| `children` | array | — | Yes | Array of child nodes |
| `repeat` | string | — | Yes | A list name (§5.1) |
| `template` | object | — | Yes | The template for repeat |
| `templates` | object | — | Yes | {"<kind>": template} |
| `templateKey` | string | — | Yes | The item key that chooses a template from templates |

Example:

```json
{ "root": { "type": "Panel", "variant": "spacer",
  "children": [
   { "type": "Modal", "id": "confirm", "text": "Quit?", "showIf": "askQuit", "pad": 16, "gap": 8,
    "children": [
     {"type": "Button", "id": "quit-yes", "text": "Yes", "action": "quit:yes", "h": 44},
     {"type": "Button", "id": "quit-no", "text": "No", "action": "quit:no", "variant": "ghost", "h": 44}
    ] }
  ] } }
```
<!-- momiji-ui-ref:end type-Modal -->

### 4.1 Enumerated values

| Key | Value | Meaning |
|---|---|---|

| `anchor` | `safe` | The whole safe area |

| `anchor` | `bottom` | Full safe-area width, at the bottom |

| `anchor` | `right` | Full height, at the right |

| `fit` | `contain` | Fits the image inside the box (may leave margins) |

<!-- momiji-ui-ref:end enums -->

### 4.2 How heights are decided

If `h` is greater than 0 it is used. Otherwise the height is measured by node type.

| Node | Height |
|---|---|
| VerticalLayout | `2·pad + Σ(2·margin + child height) + gap·(children − 1)` |
| HorizontalLayout | `2·pad + max(2·margin + child height)` |
| GridLayout | `2·pad + rows·row height + gap·(rows − 1)` (row height is the tallest child in the row) |
| Label with `wrapW` | wrapped line count × line height |
| anything else | 28 |

### 4.3 Layout containers

- **VerticalLayout, HorizontalLayout**: leftover on the main axis = inner size − Σ(size of children without `flex` + 2·margin) − gap·children. Children with `flex` share the leftover by their `flex` ratio and never go below `minH` / `minW`.
- **GridLayout**: cell width = `floor((w − 2·pad − (cols − 1)·gap) / cols)`. A child without a width gets the cell width − 2·margin.
- **ScrollView**: stacks vertically (`flex` has no effect). The scroll position is kept per `id` and clamped to `0 … (content − box)`. The scroll bar is 6 wide, 2 inside the right edge.
- **Modal**: children are stacked vertically inside the board. When two Modals under the same parent are open at once, only the one drawn last (the front one) receives input.
- **Panel**: does not lay out its children. Children of a Panel are drawn at their own `x` `y` `w` `h` (a size of 0 makes them invisible).
- **Polyline and Ellipse** do not take part in layout (they are drawn at screen positions). **Polygon** has `w` and `h`, so it can sit inside a layout container.

### 4.4 anchor

`anchor` is resolved once before drawing. Its values are in the §4.1 table. A node without `anchor` uses its `x` `y` `w` `h` as screen positions.

## 5. Values

Every time it draws, your program (the host) passes three kinds of values. The original tree from the screen JSON is not modified; the values go into a copy.

| Kind | What it affects |
|---|---|
| Strings (strings) | `{key}` inside `text`, `sprite`, `action` |
| Numbers (vars) | Conditions and `{key}` (used when there is no string with that name). Nodes with `bindVar` (Slider value, Toggle on, ToggleGroup selected) |
| Lists (lists) | Nodes laid out with `repeat` |

An unknown `{key}` stays as written (the validator does not report it).

### 5.1 repeat and template

- A node with `repeat: "<list name>"` copies its `template` once per item of the list and uses the copies as its children.
- With `templates: {"<kind>": template}` and `templateKey: "<item key>"`, the item's `item[templateKey]` chooses the template (falling back to `template`; if that is missing too, the item is not shown).
- In each copy, `{item.<key>}` in `text`, `action`, `id`, `sprite`, `enabledIf`, `highlightIf`, `showIf` and `hideIf` is replaced by the item's value. Nested repeats work the same way.
- Give nodes inside a list an `id` built from a stable data key, such as `"row:{item.id}"`.

### 5.2 Conditions

Conditions are written in `showIf`, `hideIf`, `enabledIf`, `highlightIf` and `anim.pulse.whileIf`.

- A comparison is `name operator number` (`==` `!=` `>=` `<=` `>` `<`). A number alone (true when not 0) and a name alone (true when its value is not 0) also work.
- `&&` (and), `||` (or), `!` (not) and parentheses are allowed.
- A name starts with a letter or `_` and continues with letters, digits, `_` and `.` (such as `item.potion`). Unknown names are 0.
- Pass names as numbers (vars). Strings cannot be used in conditions.

Examples: `count > 0`, `count >= 5 && ready`, `!(done) || n == 2`.

### 5.3 Order before drawing

1. Put number values into nodes with `bindVar`
2. Expand `repeat`
3. Replace `{key}`
4. Apply conditions (`enabledIf` false: not pressable; `highlightIf` true: highlighted; `showIf` false or `hideIf` true: removed with its children)
5. Lay out, draw and build the hit areas

UE's `KaedeUI::PresentScreen` and the browser's `MomijiUICanvas.present` do steps 1 to 5 in one call (§9).

## 6. Focus, hit areas and selection

### 6.1 Hit areas and focus

- **Hit areas** (pressable places) are the rectangles of pressable nodes that have an `action`. The one drawn later wins. Disabled nodes (`enabled` false) have no hit area. Outside a ScrollView's visible area nothing can be pressed.
- **Node key**: `id:<id>` when the node has an `id`, otherwise `action:<action>`. Focus, scroll position, animation and text-field contents are tracked by this key. Two nodes may share an `action`, so give nodes that hold state an `id`.
- **Moving focus** (arrow keys, gamepad): within the same group (0 outside any Modal; each Modal is its own group), focus moves to the hit area in that direction with the smallest distance + 2 × sideways offset. If the target is outside a ScrollView's visible area, the view scrolls until it is visible.
- **When a Modal opens**, focus moves to the first item inside it; when it closes, focus returns to where it was. While a Modal is open, no key or press reaches the nodes behind it.
- **The focus ring** appears only while arrow keys are in use: an orange ring 3 thick, 3 outside the hit area. Moving the pointer hides it.
- Enter and Space press the focused node of the frontmost group.

### 6.2 Selecting and copying text

- With `selectable: true` on a `Panel`, `VerticalLayout` or `ScrollView`, the **text of the Labels** inside (including the text of runs) can be selected by dragging the mouse, and it is **copied to the clipboard the moment you release** (a "copied" tag appears; there is no need for Ctrl+C).
- A selection stays within one container. Text on buttons, in text fields and in ruby cannot be selected. Touch does not select (it scrolls the content).
- Wrapped lines of the same Label are copied joined; a new Label starts a new line.
- The selection is cleared when you press outside the container, on a pressable node or on a text field, when the screen changes, or when the selected lines' text changes.

## 7. Animation

Write it in `anim`. **Animated nodes need an `id` or an `action`** (animation is tracked by that key, so without one nothing moves). In nested `anim`, the outer one wins. When the screen (the screen name the host passes) changes, the whole screen rises in over 160 ms and the previous screen's animations are dropped.

<!-- momiji-ui-ref:begin anim-keys -->
| Key | Browser | What to write |
|---|---|---|
| `enter` | Yes | {type, from, distance, durationMs, delayMs, easing}. Plays when the node is drawn for the first time (type in §4.1). 220 ms by default |
| `countUp` | Yes | {durationMs, easing}. When the text is a number (1,234 is fine) and it changed since the last draw, it counts up (immediate the first time). 400 ms by default |
| `pulse` | Yes | {scale, periodMs, whileIf}. Keeps scaling the box around its centre (the text does not move). Stops while whileIf is false. 1.06 × and 900 ms by default |
| `staggerMs` | Yes | Delays enter by the node's position among its siblings × this (lists appear one after another) |
| `blink` | UE only | {periodMs, min}. Repeats opacity between min and 1. UE only |
| `bob` | UE only | {distance, periodMs}. Bobs up and down. UE only |
| `frames` | UE only | {count, periodMs}. Steps an Image's src rectangle one frame to the right at a time. UE only |
| `exit` | UE only | {type: fade or close, durationMs}. When the node disappears it keeps being drawn for a moment while it fades or closes. UE only |
| `tween` | UE only | {durationMs}. Animates a Slider's bar from its previous value. UE only |
<!-- momiji-ui-ref:end anim-keys -->

- The values allowed for `enter`'s `type` are the three in §4.1. UE's renderer also draws `"open"` (grows vertically from the centre), but the validator (both UE and browser) reports `"open"` as `bad-value` (error), and the browser's `load` stops on that screen.

## 9. Interaction (your program's job)

Your program has four jobs: **read the screen JSON → build values from your state and draw → change the state when something is pressed → draw again.** MomijiUI handles input (pointer, wheel, scroll-bar thumb, touch scrolling, Slider dragging, arrow keys and Enter/Space, text-field editing, IME); your program receives only events. Do not interpret coordinates or hit areas yourself.

### 9.1 Events

An event is `{kind, action, nodeId, key, value, relX}`.

| kind | When | value |
|---|---|---|
| `press` | A pressable node such as a button was pressed | none |
| `submit` | Enter in a text field (Enter during IME composition is not sent) | the field's text |
| `slider` | A Slider was pressed or dragged | a number from 0 to 1 |
| `toggle` | A Toggle or ToggleGroup was pressed | Toggle: the new true/false; ToggleGroup: the index of the pressed item |

### 9.2 UE

| To do | Call |
|---|---|
| Read | `KaedeCore::LoadScreenTree(<JSON string>)` (logs an error and returns an empty tree if it cannot be read). From parsed JSON, `ScreenTreeFromJson` |
| Draw | `KaedeUI::PresentScreen(Canvas, Tree, Values, Theme, Bg, Motion, ScreenId)` (steps 1–5 of §5.3 in one call). Values are a `KaedeUI::FKaedeScreenValues` (`Strings`, `Vars`, `Lists`) |
| When pressed | `SKaedeUiCanvas::SetOnAction([](const FString& Action, float RelX){ … })` |
| Text fields | `GetTextInputValue("<bindVar>")`, `SetTextInputValue`, `SetActiveTextInput` |
| Per-screen state | `ResetScreenState(<screen name>)`, `ResetAllScreenState`, `SetScrollOffset` |
| Animation | Keep a `kaedevn::ui::UiMotionState` in your widget, pass it to `PresentScreen` and call `update(<milliseconds>)` in Tick |
| Font | `SKaedeUiCanvas::SetFontFamily` (Gothic, Mincho, Hand, Dot; §12) |
| Measure without drawing | `KaedeUI::MeasureNodeHeight`, `KaedeCore::InstantiateTemplate` |
| Check | `KaedeCore::ValidateScreenJson` (§10) |
| Look at a screen only | Launch option `-KaedeUiShot=<screen JSON>` (takes one screenshot and exits; draws with the `bind` values) |

Make your module's `*.Build.cs` depend on `MomijiUICore` and `MomijiUISlate`. The sample is `Plugins/MomijiUI/Source/MomijiUISlate/Private/Examples/SMomijiUICounterExample.cpp`.

### 9.3 Browser

| To do | Call |
|---|---|
| Read | `MomijiUICanvas.load(json)` (validates and throws if there is an error; continue with `{strict: false}`; returns `{root, host, diagnostics}`) |
| Wait for the font | `await MomijiUICanvas.loadFonts()` |
| Draw | `MomijiUICanvas.present(R, tree, {strings, vars, lists}, bg)` (`R` is `new MomijiUICanvas.Renderer(canvas)`) |
| Receive input | `MomijiUICanvas.attach(R, canvas, {stage, render, onEvent, drafts, fit})` |
| Text fields | `host.inputValue`, `host.setInputValue`, `host.focusInput` (`host` is what `attach` returns) |
| Per-screen state | `R.screenId`, `R.resetScreen`, `R.resetScreens` |
| Images | `R.imageSource`, `R.onImageLoad`, `R.onImageError` |
| Finish | `host.dispose()` (`host.detach()` to stop input only) |
| Measure or lay out without drawing | `R.measureNode`, `R.layout(tree, bg)`, `R.paint()`, `R.hitAt` |
| Check | `MomijiUICanvas.validate(doc)` (§10) |

The browser version is a single ES module with no dependencies (`momiji-ui.mjs`), plus a classic `<script>` form (`window.MomijiUICanvas`). Open it from a static HTTP server (with `file://` the font and `fetch` do not work). The browser distribution on GitHub is coming soon.

## 10. Checking (diagnostics)

Before drawing, the validator returns the following, each with its location (a JSON Pointer path). It is not called while drawing (it is a checking tool). In UE use `KaedeCore::ValidateScreenJson`, in the browser `MomijiUICanvas.validate(doc)`, and for files `node Tools/momiji-ui/validate.mjs <screen JSON …>` (one line per finding; exit code 1 if there is an error). Both implementations report the same codes at the same paths.

<!-- momiji-ui-ref:begin diagnostics -->
| Code | Severity | What | How to fix |
|---|---|---|---|
| `bad-json` | error | The file cannot be read as JSON (only node Tools/momiji-ui/validate.mjs reports it) | Fix the JSON at the reported position (brackets, commas, quotes) |
| `bad-value` | error | Wrong value type (number, string, boolean, array, object), a value outside an enumeration (anchor, fit, align, anim.enter.type), or a malformed runs or points element | Match the type in the §3 tables and the values in §4.1 |
| `dup-id` | error / warn | Two nodes have the same id (ids without {). error when a node that holds state (pressable, text field, ScrollView, Modal) is involved; warn between purely visual nodes | Use different ids. Inside a list use a data key, such as "row:{item.id}" |
| `template-missing` | error | repeat has neither template nor templates, or templateKey has no templates | Add template or templates |
| `unknown-type` | error | Unknown type (it cannot be drawn) | Use one of the 17 types in §3 (check spelling and case) |
| `bad-color` | warn | A colour that is not #rrggbb or #rrggbbaa (ignored; the default colour is used). Values starting with $ are not checked | Write #rrggbb or #rrggbbaa |
| `selectable-ignored` | warn | selectable was written on a type other than Panel, VerticalLayout or ScrollView (ignored) | Write it on the container that holds the text (Panel, VerticalLayout or ScrollView) |
| `unknown-key` | warn | Unknown key (ignored; this catches misspellings). Keys starting with _ are treated as notes and not checked | Fix the spelling to a key in the §3 tables. Start notes with _ |
<!-- momiji-ui-ref:end diagnostics -->

- Severity: an **error** cannot be drawn or will not do what you meant; a **warn** is ignored but the screen still draws.
- Unknown `{key}` is not reported (it stays, as the substitution rules say).

## 11. What is guaranteed and what is not

| Guaranteed | Not guaranteed |
|---|---|
| The same tree, the same values and the same text measurement give the same layout (rectangle positions and sizes within 1 px, text line positions within 2 px), wrapped line counts, results of repeat and conditions, hit areas, focus keys and moves and Modal opening and closing, scroll positions, heights measured without drawing, and diagnostic results | Pixel colours (glyph rendering, smoothness of corners and edges, image filtering, colour blending). They differ by drawing tool |

- This is checked against the conformance fixtures (19 in `Plugins/MomijiUI/Fixtures/`) by comparing UE with Chrome on Windows (also Chromium, Firefox and WebKit).
- **"UE only" keys and node types** (the extra drawing styles, borders, Polygon, Divider, theme shape keys, animations such as `blink`) are not drawn that way in the browser (Polygon and Divider become boxes in the panel colour). The layout guarantee applies to screens that do not use them.
- Anything drawn before the bundled font has loaded is outside the guarantee (in the browser, wait for `loadFonts` before drawing). Release Safari (macOS), Edge, macOS and Linux have not been checked.
- The supported UE is 5.8 on Windows.
